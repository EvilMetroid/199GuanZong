# 199 管综 990 道客观题审查规程 v1.2

## 1. 输入及版本锁定

仓库为 `EvilMetroid/199GuanZong`，年份 `2009—2026`，每年客观题 `01—55`。每个批次开始时记录所读 **commit SHA** 和文件路径（包括题目 Markdown、解析 Markdown、`images/YYYY_qNN.png`）。审查对象是已锁定版本，避免审查过程中题目变动而证据过时。

题目主源：`199管综真题_Markdown题库/YYYY年/YYYY年199管综真题试卷.md`。
解析主源：`199管综答案_Markdown题库/YYYY年/YYYY年199管综真题解析.md`。
逐图源：`199管综真题_Markdown题库/YYYY年/images/YYYY_qNN.png`。
全量 JSONL 用于结构及一致性检查，不能替代以上原始文件。共享题干和嵌入表格、几何图、SVG、选项均须纳入比对。PNG 通常是仓库保存的“原卷切图”，不应冒称全国正式原卷原件。

## 1.1 强制排序与双队列（2026-10-20 修订，优先于历史顺序解释）

**排序始终为年份降序（2026→2025→…→2009），同年题号升序（01→55）。不得跳过排序在前的待初审题，已审查过的题不重复挤占批次初审名额。**

- **初审队列**：尚未完成一次符合 §2 四门审核的题；通常为 `state=pending`。若 `in_review` 或 `blocked` 尚缺完整四门证据，也在初审队列中续审，但必须检查 `review_ref` 避免重复从头审查。按全库年份降序、同年题号升序取本批前 5 题，或用户指定数量。旧报告所谓“已经推导/已经看图”不算完成。
- **修复队列**：已有实质完整逐题审计证据，但有未解决缺陷，通常 `state=needs_fix`，必要时也包括已有完整核验记录的 `blocked`。修复/互证事项继续保留在 ledger 和 `ISSUE_REGISTER.md`，**不许自动改成 `accepted`，也不重复进入正常的下一批初审**。单独按严重度和证据可得性安排修复；涉及原题/解析/原图的任何修订，仍按 §5 先获用户批准。
- **已验收**：`state=accepted`，除用户明确要求复审或源版本实质变化而重新打开外，不参加上述队列。每题审完但不能验收时，必须在 review 中明确四门核验已做的范围、问题、下一步，并转入修复队列；若四门根本没有完成则保留初审队列断点，不能用状态变更掩盖漏审。
- **分开计量**：初审覆盖数 = 有本轮真实逐题四门审计记录的题数，含 `accepted` 和四门已作实质检查但有待修缺陷的题；正式 `accepted` 数必须单列，修复积压也单列；990 题全覆盖不意味着 990 道都 accepted。所有分队列数量必须由 ledger 与实际 review 内容核证，不能从状态推断虚假完成。
- **每次交接报告两个断点**：① 初审队列全局第一道尚未完成四门审查的题；② 修复队列按年份和题号排序的第一道待修题，同时报告未解决 issue 数。主流程接到“继续下一批”时默认仅推进**初审队列**；若用户明确要求修复，再处理修复队列。跨题共享题干应整体审查，但仍不可跳过前置待初审题。

每批开始必须刷新远程 `main` 的规程、`PROGRESS.md`、相应 ledger 和问题台账，检查源 commit SHA 并避免与其他批次覆盖或重复；历史重点年份推荐不能改变上述顺序。

## 2. 每题四道独立审核门

**A｜图像转录核验：** 本轮真实打开 PNG，检查题号、全部题干文字、数学符号与上下标、数字、单位、约束、A—E 五项、表格/图形和相对位置、共享题干；对照 Markdown 逐项记录“相符 / 差异 / 源图不清 / 未检查”，明确差异字句与定位。只看到文件名、自动链接存在性或程序通过都不算图像核验。必要时查看共享题干切图和年度 MD 内 SVG；若 PNG 自身疑似错误，另记录为“源图争议”，不可自行编造正确版本。

**B｜独立解题：** **先不看旧解析的推导**，从题干出发得到独立答案和可复算证明，再与旧答案比较。问题求解(01—15)：完整计算、定义域、边界、备选项。条件充分性(16—25)：分别检验(1)、(2)与必要时联合，明确充分/不充分反例，处理量词和“能确定”含义。逻辑推理(26—55)：形式化必要条件/充分条件、有效推论、逻辑反例；支持/削弱/解释型要比较各选项相关性与强度；分析推理完整约束穷举或给足够的排他证明。含图题需要正确使用实际原图几何/位置。程序穷举可作辅证，但须提供代码/约束模型或最少可复算输入与输出，不能写“穷举证实”而不留证据。

**C｜原答案核验：** 明确写“仓库答案：X；独立答案：Y；是否一致；选项是否唯一或最佳”。存在重复正确选项、无正确选项、多解、不可判时标记阻断或争议，不强行算通过。

**D｜原解析逐步审计：** 与原解析逐句比较：每步计算、等价变形、逆否/反推、条件使用、证据充分性、文字清晰度。独立算出同一答案不等于原解析正确。明确判定：正确且清楚 / 结论正确但步骤错误 / 正确但缺少关键步骤 / 错误 / 存疑。发现错误要引用原句、给反例或正确推导，不能只写“推导不严谨”。

**四道门都通过且证据链接可访问，才有资格把该题标记为 `accepted`。**

## 3. 状态和证据分级

台账字段：
- `state`: `pending` 未开始；`in_review` 处理中但未完；`accepted` 四道门完成、暂无阻断问题；`needs_fix` 检出缺陷待修；`blocked` 材料缺失、歧义或证据不足。**有问题的题不能仅因“发现问题”而判 accepted**。
- `image_check`: `pending`, `matched`, `mismatch`, `source_ambiguous`, `blocked`。
- `independent_solution`: `pending`, `proven`, `disputed`, `blocked`。
- `explanation_check`: `pending`, `pass`, `flawed`, `incomplete`, `blocked`。
- `review_ref`: 指向 `reviews/YYYY-NN-MM.md#YYYY-NN` 的**实际内容**，不能只放占位链接。
- `issue_ids`: 指向问题台账；没有问题时用 `—`。

历史记录中“65 题已推导、26 题已看图”只属于 **legacy lead / 待复核线索**。新的权威计数必须来自最新台账实际状态，不得从历史报告直接继承。

## 4. 问题分类、严重度和处置

分类：`Q` 题干/选项转录错误、`S` 源图争议、`A` 标准答案错误/不唯一、`P` 推理或计算错误、`I` 关键推理缺省、`T` 术语/排版/OCR、`V` 资料不足。
严重度：`critical` 导致无法正常作答或多答案；`high` 答案/核心推理错误；`medium` 主要步骤缺失、图表不可靠；`low` 无害表述问题。

每个问题独占一条，至少写：ID、题号、题目/解析/PNG 的相对路径与 commit、问题分类及严重度、证据原文、独立证明或最小反例、影响、建议改正文本、审查状态、是否需正式卷面互证、处置记录。不能合并省略“其他若干题”。

区分 **“仓库 Markdown 与 PNG 不符”** 和 **“仓库 PNG 自身疑似失真/非官方回忆版本”**。网络第三方版本仅作互证，证据冲突时保留两个版本及来源，不未经证据擅改源文件。

## 5. Work 批次提交规范（避免长任务失控）

- 正常每批 **5—10 道**，极复杂逻辑组可缩至 2—5 道；需要实际多工具访问时按题组自适应。不要仅为了赶数量牺牲证明。
- 每批开始读取本规程、`PROGRESS.md`、年度 ledger、对应源文件与历史 issue；按 §1.1 **初审队列**的未审题号选题、独立保留**修复队列**，确保不重叠、不漏审；共用题干题组应一起处理。
- 输出新证据 `audit/reviews/YYYY-NN-MM.md`（也可同批多个），写清每题原文关键信息/原图差异/独立证明/选项分析/原解析逐步审计/判定/问题链接。
- 更新年度 ledger 精确对应行；更正问题则更新 `ISSUE_REGISTER.md` 或追加独立 issue 文档；更新 `PROGRESS.md` 的数字与断点，并在末尾追加 commit 记录。
- 提交前检查题数、题号无缺漏与重复、所有 accepted 都有四门证据及可访问 review_ref、统计来自 ledger 而非手填宣称。没有条件验证的条目保留 `blocked` / `in_review`，不要伪造。
- 默认仅修改 `audit/`，**不修改原题、解析、图像和派生 JSONL**；要实施修复，先另开 PR、给 diff 和影响分析并征得用户确认。不得运行 README 特别警告会覆盖校对结果的脚本。
- 原始文件可能被其他分支或 Work 修改；每次写入前刷新远程状态。遇冲突，不覆盖其他批次记录；合并证据后再提交。
- 每次 Work 结束须汇报：本批范围、证据文件路径、每题状态、问题 ID、仍未完成数、提交 SHA/PR URL、下一批最小未完成范围。做不到就如实报告。
- 若任务因限额、时长中止，先写入本批已完成证据及未完成断点；不要在没有任务/工具支持时承诺将自动恢复。

## 6. 接受测试

新一轮 `accepted` 数、`image_check=matched` 或已记录源图差异的实际核验数、`independent_solution=proven` 数、`explanation_check` 已审数分别独立统计，不可互相推算；不同状态计数必须符合每年 55 / 全年 990。

只有 990 题均完成四门审核且全部 blocking 问题得到处置或明确作为未解决争议披露，才能声称“完成全面审查”；**全面审查完成不代表仓库全无错误**。
