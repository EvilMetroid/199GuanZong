# 199 管综客观题独立审查中心

本目录用于 **2009—2026 年 18 套试卷 × 每套 55 道客观题 = 990 题**的独立解题、原卷 PNG 逐张比对、解析质量审查和纠错跟踪。第 56—57 题写作不计入此轮验收范围。

## 重要原则

- **当前并未完成 990 题审查。** 之前 Chat 留下的“65 题独立推导、26 张原图、20 项问题”属于 **历史声称的进度与线索**，未按本审查规程重新验收；不得计入新一轮正式认证。
- 所有条目在 `ledger/` 中从 `pending` 起步；必须按 `REVIEW_PROTOCOL.md` 的证据门槛逐项升级。
- 原试题、解析 Markdown 是题库内容源，JSONL 是派生产物；**审查目录的台账才是审查状态的事实来源**。在正式审查过程中不要顺手覆盖题库源文件或重新运行可能抹掉手工校核的 OCR 脚本。
- **一题一记录、一问题一条目**；无问题也须给独立推导、截图对照信息、与原解析逐步核对后的结论。
- 未独立证明 ≠ 正确；截图链接存在 ≠ 读过截图；找到相同答案 ≠ 已审原解析；只比对单一来源截图 ≠ 已与国家正式原卷比对。
- 重要勘误按时间顺序追溯；历史报告不直接替代新核验。

## 推荐使用方式

1. 将 [WORK_PROMPTS.md](WORK_PROMPTS.md) 的「首次启动 / 首批 Work」完整提交给 Work。
2. 一次处理 **5—10 题**，同一批必须完成独立解题、逐图对照、原解析逐步核对，不能只做其中一环就标记完成。复杂共用题干按题组一起处理。
3. 每批至少更新三处：`reviews/` 的逐题证据、对应 `ledger/YYYY.md`、`PROGRESS.md`；发现问题则还要更新问题台账。
4. 结束每批后提交 GitHub，回报本批范围、核实数、问题 ID、下一批题号、提交链接或 PR。
5. 先 2022/2025/2026 等已有问题年份也可，但一旦选定年度/范围，必须避免漏题和重复计算；默认根据未完成的最小题号推进。

## 完成定义

只有 **990/990** 道均存在独立可复算解题证据、**990/990** 对应 PNG 已真实逐张核对、**990/990** 原解析逻辑逐步评价，且问题已逐项处置或明确保留争议，方可把全库标记为“审查覆盖已完成”。“全部正确”是另一个更严格的结论，不能凭覆盖率宣称。
