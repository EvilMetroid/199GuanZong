## 一、背景与“双轨制”核心设计理念

### 1. 传统位图切片（PNG/JPG）的痛点
在构建智能化大模型题库及 RAG 知识检索系统时，单纯依赖截图切片存在三大致命局限：
1. **语义不可读**：向量数据库仅能检索题干文字，对于“图形中 $DE$ 与 $BF$ 交于 $O$”、“集装箱从下到上堆叠为 A-B-C”等关键空间关系，缺乏纯文本向量表征，模型无法仅通过文本理解题意。
2. **跨平台渲染失真**：位图在不同分辨率、Retina 屏幕以及高分屏下放大容易模糊；在深色模式（Dark Mode）下黑色线条与黑色背景融为一体，难以阅读。
3. **不可编辑与不可提取**：用户无法复制图中的几何参数、拓扑结构。

### 2. 双轨制（Dual-track Principle）
为兼顾**原卷绝对真实性**与**数字化先进性**，本项目确立了**双轨并存**原则：
* **第一轨（Ground Truth）**：试卷中**永久保留**原卷高清切片（`![...](images/YYYY_qNN.png)`），作为核对排版、印刷细节的绝对事实基准。
* **第二轨（Text-based Vector）**：紧跟在原图下方补充纯文本代码（内联 `<svg>`、Unicode 符号或 Markdown 表格）。
* **收益**：
  - 人工阅读时，既可查看原卷扫描件，又可获得矢量高清放大与平滑缩放体验；
  - 大模型 RAG 解析时，构建脚本 `build_rag_chunks_from_md.py` 会把 `<svg>` 块整块剔除（见[第六节](#六rag-检索流水线兼容性与自动化质检验证)）：像素坐标与样式属性对向量嵌入是纯噪声，且画布坐标不是数学坐标；图形语义由 `image` 字段引用的原卷切片 + 题干文字承载，SVG 只服务于人工阅读。

## 三、Markdown 与 RAG 体系中的 SVG 四大工程铁律

在 Markdown 文档中嵌入原生 HTML/SVG 时，由于各大解析器（CommonMark、Goldmark、Typora、VS Code Webview、GitHub）的行为差异，必须遵守以下四条硬性规范：

### 1. 空行绝迹铁律（Zero Blank Line Rule）
* **底层机制**：根据 CommonMark 标准，解析器在遇到原生 HTML 块时会保持原样直通；**但一旦在 HTML 块内部遇到任何空行（即仅含换行或空格的空行），解析器便会强制认为该 HTML 块已结束，从而切换回 Markdown 文本解析模式**！
* **后果**：空行之后的所有 SVG 标签（如 `<path ...>`, `<circle ...>`）会被误当成普通段落甚至行内代码，造成标签截断、未闭合或完全空白。
* **铁律**：**`<svg>...</svg>` 标签对内部严禁包含任何空行！** 全部代码必须行行连续。

### 2. 放弃 Pattern 填充，拥抱可靠实体色（Solid Fill Rule）
* **惨痛教训**：在 2026 年第 14 题与 2024 年第 8 题初版中，曾尝试使用 `<defs><pattern id="hatch">` 绘制 $45^\circ$ 排线阴影。但在 VS Code Webview、Typora 和 GitHub 网页中，内部引用的 `url(#hatch)` 常被作用域隔离或安全沙箱过滤，导致用户看到完全透明的空白！
* **铁律**：**一律采用直观可靠的实体颜色填充**：
  - 平面阴影推荐柔和淡浅灰（`fill="#cbd5e1"` 或 `#e2e8f0"`）或柔和浅蓝（`fill="#bae6fd"`）；
  - 边框采用深色线条（`stroke="#222"` 或 `#0284c7"`，`stroke-width="1.8"`）；
  - 排线效果若确有需要，可用离散 `<line>` 搭配 `stroke-dasharray="3,3"` 直接手绘，杜绝依赖 `<defs>`。

### 3. 自适应视口与背景隔离（ViewBox & Container Rule）
* **必须声明**：`<svg viewBox="0 0 W H" width="W" height="H" xmlns="http://www.w3.org/2000/svg" style="display:block;margin:12px auto;background:#fff;">`。
* **原因**：
  - `viewBox` 保证不同屏幕与窗口宽度下等比例自适应缩放；
  - `style="background:#fff;"` 极其关键：在夜间模式/深色主题（Dark Mode）下，强制提供白色画布背景，确保原黑色/深色线条无论在何种主题下都清晰可见。

### 4. 标准 XML 严格自闭合（Self-closing Rule）
* **规范**：所有无子标签的单标签必须显式自闭合（`<circle ... />`, `<line ... />`, `<rect ... />`, `<path ... />`, `<polygon ... />`）。
* **文本标签**：`<text ...>内容</text>` 必须配对闭合。

## 四、典型管综题型 SVG 绘制实战与几何精修技巧

### 案例 1：立体几何视线遮挡与方程对齐（2026 年第 6 题）
* **题目背景**：正方体一个顶点位于球心，正方体棱长为 1，球半径为 1，正方体向球体左前下方伸出。
* **难点与技巧**：
  1. **内部棱与外部棱虚实反转**：球心位于球体深处内部，从球心引出的 3 条连向正方体顶点的棱（水平向左、竖直向下、轴测斜向左前）**全部处于球体内部，必须为虚线**（`stroke-dasharray="4 3"`）；朝向观察者的外侧表面 9 条棱**必须为实线**。
  2. **正方体顶点严格满足赤道椭圆方程**：
     - 正方体斜向左前的顶面侧边端点 $V_2(x_0-\Delta x, y_0+\Delta y)$ 位于球体赤道面上，其坐标必须落在赤道椭圆上：
       $$\frac{(\Delta x)^2}{R^2} + \frac{(\Delta y)^2}{b^2} = 1$$
     - 设球半径 $R = 70$，椭圆短轴 $b = 25$。取 $\Delta x = 32$，则推导 $\Delta y = 25 \times \sqrt{1 - (32/70)^2} \approx 22$。端点 $(118, 107)$ 严密契合椭圆曲线，杜绝“顶点悬空脱离椭圆”的尴尬。
  3. **外轮廓遮挡与 1/4 虚线弧**：
     - 球体左下象限被正方体外部遮挡，从左赤道端点到南极点之间的 **$90^\circ$ 圆弧段为虚线**（`d="M 80 85 A 70 70 0 0 0 150 155" stroke-dasharray="3 3"`）；其余 $270^\circ$ 圆弧为实线。

  <!-- 球体左下方1/4虚线圆弧 -->
  <path d="M 80 85 A 70 70 0 0 0 150 155" fill="none" stroke="#64748b" stroke-width="1.6" stroke-dasharray="3 3" />
  <!-- 赤道椭圆后半周 (虚线) 与 前半周 (实线) -->
  <path d="M 80 85 A 70 25 0 0 1 220 85" fill="none" stroke="#64748b" stroke-width="1.4" stroke-dasharray="3 3" />
  <path d="M 80 85 A 70 25 0 0 0 220 85" fill="none" stroke="#0ea5e9" stroke-width="1.8" />

### 案例 2：同心半球体挖空与下沉虚线（2025 年第 6 题）
* **题目背景**：大半球中挖去同心小半球，小半球直径为大半球一半。
* **难点与技巧**：
  1. **杜绝竖直台阶折线**：挖掘出的空腔是“球冠曲面”，不能画成带有垂直壁的平底圆柱槽。

### 案例 3：平面阴影面积差与圆弧围合（2024 年第 8 题、2026 年第 14 题）
* **难点与技巧**：
  - 在 SVG `path` 的圆弧指令 `A rx ry x-axis-rotation large-arc sweep-flag x y` 中，`sweep-flag` 控制顺时针（1）还是逆时针（0）。
  - 当多个圆弧首尾相连围成阴影时，必须按照严格的闭合环路计算每一段圆弧的旋向；**一旦某一段方向写反，圆弧会反向膨胀鼓出，在视觉上形成一条穿透画面的多余伪线**。
  - **精简原则**：阴影 `<path ... Z>` 本身就已经包含了圆弧边界，不需要再单独额外绘制重复的 `<path>` 弧线，避免微小精度误差造成“双线重影”。

### 案例 4：空间几何体比例与浸没层叠（2024 年第 13 题）
* **题目背景**：底面半径 $2r$ 的圆柱容器，放入半径 $r$ 的铁球后，液面高度为 $r$。
* **比例调优法则**：
  - 原题中容器底面直径 $4r$，铁球直径 $2r$。容器宽高比约为 $3:1$，属于非常扁平宽矮的容器（高度仅约 $1.3r\sim 1.4r$）。
  - 球体沉底后，球心恰好位于液面处，球顶（高度 $2r$）几乎齐平容器上沿口。
  - 绘制时务必按照真实比例建立几何坐标系，杜绝机械套用高瘦圆柱导致视觉比例失真。

### 案例 5：六边形密铺与离散蜂窝拓扑（2026 年第 31 题）
* **六边形平顶（Flat-top）数学参数模型**：
  - 外接圆半径 $s$，垂直半高 $dy = \frac{\sqrt{3}}{2}s$，水平列距 $dx = 1.5s$。
  - 每个正六边形的 6 个顶点公式：
    $$(cx+s, cy),\; (cx+\frac{s}{2}, cy+dy),\; (cx-\frac{s}{2}, cy+dy),\; (cx-s, cy),\; (cx-\frac{s}{2}, cy-dy),\; (cx+\frac{s}{2}, cy-dy)$$
  - 相邻两列六边形在垂直方向自然交错 $dy$。该算法可保证多达数十个六边形紧密拼接无缝隙、无重叠。

* **警惕纯文字遗漏**：部分排列组合题目题干仅用“堆放成两组”模糊指代，并未用文字交代字母顺序，**全部信息隐藏在插图中**。

## 六、RAG 检索流水线兼容性与自动化质检验证

### 1. 切分脚本的 SVG 剔除机制
题库构建脚本 `build_rag_chunks_from_md.py` 解析时先经 `drop_svg()` 把
`<svg>...</svg>` 块整块剥离（人读插图不进 chunk 文本：XML 坐标与样式属性
对向量嵌入是纯噪声，且画布坐标不是数学坐标，模型无法从中推出几何关系），
其余行按规则归位：
```python
mi = IMG.match(ln)           # ![...](images/...) -> chunk["image"](原卷切片)
if mi:
    chunk["image"] = mi.group(1)
mo = OPT.match(ln)           # "- **A**．..." -> chunk["options"]["A"]
if mo:
    chunk["options"][mo.group(1)] = mo.group(2)
else:
    body_lines.append(ln)    # 其余行 -> 题干 stem
```
* **结论**：SVG 补图只影响人工阅读，不影响切分。`image` 始终指向原卷切片，
图形语义由原卷图 + 题干文字承载；chunk 文本零 SVG 残留
（全库构建 0 告警可验证，详见[第 2 节质检命令](#2-全量自动化质检命令)）。
